# 2026-08-06 — 문·자물쇠 스폰 구조 확정(자물쇠 별도 스폰 전환)

## 요약

문 프리팹 제작 방법 질의에서 시작해, 조립체 전체(벽·문틀·문짝)를 단일 NetworkObject 로 만들고 셋업을 자동화하는 툴(`Tools/Map/문 프리팹 셋업`)을 붙였다. 처음에는 자물쇠·손잡이 판정면을 프리팹 루트에 고정했으나, 사용자 지적으로 열린 문간에 판정면이 남아 레이를 가로채는 결함을 확인하고 문짝 자식으로 이동했다. 이어 사용자가 "자물쇠는 이미 만든 Lock 변종 프리팹을 동적 스폰하는 게 맞다"고 방향을 확정해, 문 내장 LockFace/비주얼 토글 방식을 폐기하고 문은 `LockPos` 앵커만 제공 + 스포너가 번호별 자물쇠 변종을 별도 NetworkObject 로 스폰 + 해정 승인 시 서버가 자물쇠를 소멸시키는 구조로 재설계했다. 손잡이는 양쪽 문짝에 하나씩 두되 확정이 문 루트 RPC 하나로 모여 어느 쪽을 조작해도 동일하게 동작함을 확인했다. 에디터 쪽에서는 셋업 툴 실행 산출물(채널 SO·레지스트리·MapGenManager·플레이어 배선·DoorAnim·NetworkPrefabs)이 확보됐다.

## 문 프리팹 체계 (28da7e3, 58ef6ed)

- Door.prefab = 조립체 전체 단일 NetworkObject 확정 — 조립기는 벽에 구멍+DoorAnchor 만 남기고, 문 프리팹이 슬롯을 통째로 메운다. 문짝 이동은 NetworkTransform 없이 isOpen bool 복제 + 로컬 애니메이터
- `DoorPrefabSetup`(Tools/Map/문 프리팹 셋업, 멱등): NetworkObject·DoorInteractable·Animator·NavMeshObstacle(전폭 Carve 1개) 부착, 문짝 개방 스윙 클립 2종+IsOpen 컨트롤러 자동 생성, 레지스트리·NetworkPrefabs 등재
- 판정면을 루트 고정 → 문짝 자식으로 수정: 개방 후 문간에 남은 투명 트리거가 문틈 너머 조준 레이를 가로채는 결함 제거. 콜라이더는 문짝 메시 실측 바운드 맞춤

## 자물쇠 별도 스폰 전환 (e47c98e)

- 사용자 확정: 자물쇠는 문 내장 면이 아니라 기존 Lock 변종 프리팹을 동적 스폰 — `lockVisualsByPair` 토글 방식 폐기
- `DoorLockFace` 를 스폰형 자물쇠 프리팹 루트 컴포넌트로 개편 — 문 참조는 `NetworkVariable(NetworkBehaviourReference)` 복제(늦은 합류 포함), 확정은 문 루트 서버 RPC 유지
- 스포너: DoorLocked 문마다 `LockPrefabs[번호-1]` 를 문의 `LockPos` 에 스폰, 문↔자물쇠 상호 연결. 해정 승인 시 문이 자물쇠를 서버 소멸(별도 오브젝트라 문짝 스윙 미추종 — 남기면 허공에 뜬다)
- 손잡이 면은 HandleFace_L/R 양쪽 문짝 — 복수 판정면이 같은 루트 RPC 로 모여 동작 동일(영구 개방이라 닫기는 없음)
- 레지스트리 `LockPrefabs` 추가, 인스펙터 변종 섹션 공용화(열쇠·자물쇠 각 5칸 — 최대 쌍 수 = 중요 물품 문 2 + 지름길 3)
